# 打包與部署

## 概述

Spring Boot 應用程式可以打包成**可執行的 Fat JAR**（包含所有依賴和內嵌伺服器），直接用 `java -jar` 執行，不需要安裝 Tomcat 等外部伺服器。

---

## 建置可執行 JAR

### 使用 Maven

```bash
# 清除並打包（跳過測試加速建置）
./mvnw clean package -DskipTests

# 包含測試
./mvnw clean package

# 打包後產生的 JAR 位於 target/ 目錄
ls -la target/*.jar
# target/demo-0.0.1-SNAPSHOT.jar  ← 可執行的 Fat JAR
```

### 確認 pom.xml 有 spring-boot-maven-plugin

```xml
<build>
    <plugins>
        <plugin>
            <groupId>org.springframework.boot</groupId>
            <artifactId>spring-boot-maven-plugin</artifactId>
            <!-- 排除 DevTools（避免意外打包進生產環境） -->
            <configuration>
                <excludeDevtools>true</excludeDevtools>
            </configuration>
        </plugin>
    </plugins>
</build>
```

---

## 執行 JAR 檔案

```bash
# 基本執行
java -jar target/demo-0.0.1-SNAPSHOT.jar

# 指定 Profile（生產環境）
java -jar app.jar --spring.profiles.active=prod

# 覆寫設定（命令列參數優先級最高）
java -jar app.jar --server.port=9090 --spring.datasource.url=jdbc:mysql://db/prod

# 設定 JVM 參數
java -Xms512m -Xmx1g -jar app.jar

# 所有設定合在一起
java -Xms512m -Xmx1g \
     -Dspring.profiles.active=prod \
     -jar app.jar \
     --server.port=9090
```

## 多環境配置

```
src/main/resources/
├── application.properties          ← 共用設定
├── application-dev.properties      ← 開發環境
├── application-test.properties     ← 測試環境
└── application-prod.properties     ← 生產環境
```

```properties
# application.properties（共用）
spring.application.name=my-app
server.port=8080

# application-prod.properties（生產）
spring.datasource.url=${DB_URL}
spring.datasource.username=${DB_USER}
spring.datasource.password=${DB_PASSWORD}
spring.jpa.show-sql=false
logging.level.root=WARN
```

## Docker 部署

### 建立 Dockerfile

```dockerfile
# 方法一：單階段建置（簡單）
FROM openjdk:11-jre-slim

# 建立工作目錄
WORKDIR /app

# 複製 JAR 檔案
COPY target/demo-0.0.1-SNAPSHOT.jar app.jar

# 暴露埠號
EXPOSE 8080

# 設定執行命令
ENTRYPOINT ["java", "-jar", "app.jar"]
```

```dockerfile
# 方法二：多階段建置（建議用於生產）
# 第一階段：建置
FROM maven:3.8-openjdk-11 AS build

WORKDIR /app
COPY pom.xml .
COPY src ./src

# 下載依賴並建置（--no-transfer-progress 減少輸出）
RUN mvn clean package -DskipTests --no-transfer-progress

# 第二階段：執行
FROM openjdk:11-jre-slim

WORKDIR /app

# 只複製最終 JAR，不包含建置工具
COPY --from=build /app/target/demo-0.0.1-SNAPSHOT.jar app.jar

EXPOSE 8080

# 設定時區
ENV TZ=Asia/Taipei
RUN ln -snf /usr/share/zoneinfo/$TZ /etc/localtime

# 建議加上健康檢查（配合 [[07-Spring-Boot-Actuator]]）
HEALTHCHECK --interval=30s --timeout=10s --start-period=30s --retries=3 \
    CMD wget -qO- http://localhost:8080/actuator/health || exit 1

ENTRYPOINT ["java", \
    "-Xms256m", \
    "-Xmx512m", \
    "-XX:+UseContainerSupport", \
    "-jar", "app.jar"]
```

### 建置與執行 Docker Image

```bash
# 建置 image
docker build -t my-app:1.0.0 .

# 執行容器
docker run -d \
    --name my-app \
    -p 8080:8080 \
    -e SPRING_PROFILES_ACTIVE=prod \
    -e DB_URL=jdbc:mysql://db:3306/mydb \
    -e DB_USER=root \
    -e DB_PASSWORD=secret \
    my-app:1.0.0

# 查看日誌
docker logs -f my-app
```

## Docker Compose（多服務）

```yaml
# docker-compose.yml

version: '3.8'

services:
  # 應用程式
  app:
    build: .
    ports:
      - "8080:8080"
    environment:
      SPRING_PROFILES_ACTIVE: prod
      SPRING_DATASOURCE_URL: jdbc:mysql://mysql:3306/mydb
      SPRING_DATASOURCE_USERNAME: root
      SPRING_DATASOURCE_PASSWORD: secret
      SPRING_REDIS_HOST: redis
    depends_on:
      - mysql
      - redis
    networks:
      - app-network
    healthcheck:
      test: ["CMD", "wget", "-qO-", "http://localhost:8080/actuator/health"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s

  # MySQL 資料庫
  mysql:
    image: mysql:8.0
    environment:
      MYSQL_ROOT_PASSWORD: secret
      MYSQL_DATABASE: mydb
      MYSQL_CHARACTER_SET_SERVER: utf8mb4
    volumes:
      - mysql-data:/var/lib/mysql
      - ./sql/init.sql:/docker-entrypoint-initdb.d/init.sql
    networks:
      - app-network
    healthcheck:
      test: ["CMD", "mysqladmin", "ping", "-h", "localhost"]
      interval: 10s
      timeout: 5s
      retries: 5

  # Redis 快取
  redis:
    image: redis:7-alpine
    command: redis-server --requirepass redispassword
    volumes:
      - redis-data:/data
    networks:
      - app-network

volumes:
  mysql-data:
  redis-data:

networks:
  app-network:
    driver: bridge
```

```bash
# 啟動所有服務
docker-compose up -d

# 查看狀態
docker-compose ps

# 查看日誌
docker-compose logs -f app

# 停止所有服務
docker-compose down

# 停止並刪除資料卷
docker-compose down -v
```

## Spring Boot Layered JAR（最佳化 Docker）

Spring Boot 2.3+ 支援分層 JAR，改善 Docker 快取效率：

```dockerfile
# 使用分層解壓
FROM openjdk:11-jre-slim AS builder
WORKDIR /app
COPY target/demo-0.0.1-SNAPSHOT.jar app.jar

# 解壓分層
RUN java -Djarmode=layertools -jar app.jar extract

FROM openjdk:11-jre-slim
WORKDIR /app

# 分開複製各層（優先使用 Docker 快取）
COPY --from=builder /app/dependencies/ ./
COPY --from=builder /app/spring-boot-loader/ ./
COPY --from=builder /app/snapshot-dependencies/ ./
COPY --from=builder /app/application/ ./

# 第三方依賴（最少改變，快取最久）、Spring Boot loader、應用程式程式碼（最常改變）
ENTRYPOINT ["java", "org.springframework.boot.loader.JarLauncher"]
```

## Kubernetes 部署（進階）

```yaml
# k8s-deployment.yaml

apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
  labels:
    app: my-app
spec:
  replicas: 3
  selector:
    matchLabels:
      app: my-app
  template:
    metadata:
      labels:
        app: my-app
    spec:
      containers:
        - name: my-app
          image: my-registry/my-app:1.0.0
          ports:
            - containerPort: 8080
          env:
            - name: SPRING_PROFILES_ACTIVE
              value: prod
            - name: DB_PASSWORD
              valueFrom:
                secretKeyRef:   # 從 K8s Secret 取得密碼
                  name: db-secret
                  key: password
          resources:
            requests:
              memory: "256Mi"
              cpu: "250m"
            limits:
              memory: "512Mi"
              cpu: "500m"
          livenessProbe:         # 存活探針（失敗時重啟容器）
            httpGet:
              path: /actuator/health/liveness
              port: 8080
            initialDelaySeconds: 30
            periodSeconds: 10
          readinessProbe:        # 就緒探針（未就緒時不路由流量）
            httpGet:
              path: /actuator/health/readiness
              port: 8080
            initialDelaySeconds: 20
            periodSeconds: 5

---
apiVersion: v1
kind: Service
metadata:
  name: my-app-service
spec:
  selector:
    app: my-app
  ports:
    - port: 80
      targetPort: 8080
  type: LoadBalancer
```

```properties
# application.properties（Kubernetes 健康探針設定）
management.endpoint.health.probes.enabled=true
management.health.livenessState.enabled=true
management.health.readinessState.enabled=true
management.endpoints.web.exposure.include=health,info,prometheus
```

## 部署為 Linux 服務（Systemd）

```bash
# 建立 systemd service 檔案
sudo vim /etc/systemd/system/myapp.service
```

```ini
[Unit]
Description=My Spring Boot Application
After=network.target

[Service]
User=appuser
Group=appuser
WorkingDirectory=/opt/myapp
ExecStart=/usr/bin/java -Xms256m -Xmx512m -jar /opt/myapp/app.jar
StandardOutput=journal
StandardError=journal
SyslogIdentifier=myapp
Restart=on-failure
RestartSec=5
EnvironmentFile=/opt/myapp/.env

[Install]
WantedBy=multi-user.target
```

```bash
# 設定環境變數檔案
sudo vim /opt/myapp/.env
```

```
SPRING_PROFILES_ACTIVE=prod
DB_URL=jdbc:mysql://localhost:3306/mydb
DB_USER=appuser
DB_PASSWORD=secure_password
```

```bash
# 啟用並啟動服務
sudo systemctl daemon-reload
sudo systemctl enable myapp
sudo systemctl start myapp

# 查看狀態和日誌
sudo systemctl status myapp
sudo journalctl -u myapp -f
```

## 建置資訊（Build Info）

```xml
<!-- pom.xml -->
<plugin>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-maven-plugin</artifactId>
    <executions>
        <execution>
            <goals>
                <!-- 生成 build-info.properties，讓 Actuator /info 顯示建置資訊 -->
                <goal>build-info</goal>
            </goals>
        </execution>
    </executions>
</plugin>
```

## 重點整理

- `mvn clean package` 打包成可執行 Fat JAR
- 使用 `--spring.profiles.active=prod` 指定生產環境 Profile
- Docker 多階段建置讓 Image 更小
- Docker Compose 方便本地開發時啟動所有服務
- Kubernetes 部署時設定 `livenessProbe` 和 `readinessProbe`
- 敏感設定（密碼）使用環境變數或 K8s Secret，不寫在設定檔中
